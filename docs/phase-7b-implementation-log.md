## Decisions worth knowing
- **A portal click is not an acceptance.** The specification (P708 §6) and ADM-08d have the client accept and staff record it with evidence. The portal therefore writes a request; only `p7_client_acceptances`, written through `record_client_acceptance` by a person with delivery rights, is read by the completion gate. A client calling the acceptance door directly is refused (verifier, red-proved by removing its role check).
- **ARCHIVING/ARCHIVED are a column, not two more `state` values.** `p7_set_state`, `phase_seven_guard` and five doors test `state in ('completed', 'phase8_ready')`; widening `state` would have silently re-opened them for an archived project. The verifier proves an archived project still refuses a deployment plan.
- **No invented duration.** With no Admin-set policy an archive cannot start. The portal's read-only state and expiry come from the archive's frozen snapshot of the policy.
- **Two layers, red-proved together.** A request's note, a decision's text and a policy reason are refused by a door check AND a table CHECK; removing the door check leaves the CHECK raising (the mutation still fails the verifier). The settle door and `record_client_acceptance` both check delivery rights, so the client-cannot-confirm check was proved by removing both, and the decline path (which has only the first) by removing the first.
- **The Orchestrator's routing is HELD today and says so.** The Phase 7 agents are disabled and hold no tool. The routed branch is exercised in the pure tests with an injected tool binding, and in the verifier by enabling the agents inside the rolled-back transaction.

- Real deployment execution, production tools, enabling any Phase 7 agent: need credentials and an owner decision (P7-M001, P7-M008). Every agent-bound task is held.
- Disposal of an expired record: no door deletes anything; a person decides, and no such decision door exists.
- Mounting the staff panel and the portal link on their pages (shared files, not edited): P7-M016. Nothing was rendered in a browser: P7-M017.
- `project.completed` does not start archiving: archiving needs an Admin and a policy.
- The Phase 8 start itself stays a person's act (warranty window); the subscriber only fills the intake.
- ClientActionRequest, a Phase 7 Failure Queue, a client financial statement view and an automatic handover-draft creation were left for Phase 7c and are built there (`docs/phase-7c-implementation-log.md`).
